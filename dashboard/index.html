How the radar works

The value model

A protocol's implied value is its TVL times five multipliers:

  1. Peer — the category peer multiple: the median market-cap-to-TVL ratio of the category's live-token protocols, each ratio clipped to 0.02–2.0, shrunk toward the global median with 5 pseudo-observations, capped to 0.05–1.0. Categories with fewer than 3 live peers take the global median.
  2. Growth — 1 + the 7-day TVL change (clamped to −50%…+80%) × 0.4 ÷ 100.
  3. Maturity — 0.7 + min(age in days, 1460) ÷ 1460 × 0.3. Older protocols that still record no token have waited longer, so they count for more.
  4. Size — TVL in billions raised to −0.07, clamped to 0.75–1.20. Very large TVL is discounted slightly, small TVL is lifted slightly.
  5. Chains — 1 + 0.02 × min(chain count, 5).

Every multiplier is rounded to 4 decimals before the value is computed, and each board row carries its rounded multipliers, so the detail drawer recomputes the row's value exactly from them alone. The result is rounded to a whole dollar.

What gets ranked

The board ranks every protocol that records no token: the whole 40-protocol watchlist (TVL at or above $50M), plus every rankable pre-token protocol below that floor, except bridged products — a bridge moves a token that already exists, so it is not a launch of its own. Protocols above the floor that the watchlist leaves out stay out for the same reason the watchlist leaves them out. Protocols that record a token are set aside with their market caps and never ranked.

What the numbers do not say

"Records no token" is a statement about the snapshot's record, never proof that a protocol has no token. The implied value is this radar's own claim about what a launch would be worth if the protocol's record stayed as it is; it does not predict whether or when a token is issued, and it is not a price. Farm plans are generic steps with stated costs and times — check the protocol's own app before acting, and never approve an unlimited spend.
